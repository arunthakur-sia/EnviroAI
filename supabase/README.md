# EnviroAI data for Supabase

Generated by `python3 -I scripts/export-postgres.py` from a freshly seeded
`npm run seed` database (144 tables, 17,945 rows).

Paste into the Supabase SQL editor, in this order:

1. `00_schema.sql`
2. `01_data_01.sql` ... `01_data_11.sql` (one at a time, in order; each under ~1 MB)
3. `02_indexes.sql`
4. `03_lock_down.sql`

Verified by loading all files into a clean Postgres (PGlite): all row counts match.

Not included: SQLite full-text search tables (`chunks_fts`, `records_fts`),
triggers and foreign keys. The running app still uses SQLite; it does not read
from Supabase until the runtime is ported. Uploaded files and reports are on
disk under `data/`, not in the database.

If you already ran `01_data_01` to `01_data_05` from the first export, run `01_data_06` to `01_data_11` next and discard the older 06 to 08 (they are the same rows in smaller pieces).
